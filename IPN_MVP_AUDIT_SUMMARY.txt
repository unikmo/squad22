IPN MVP AUDIT SUMMARY (current repo state)

Executive summary
- Consumer-facing UI is largely implemented using mocked, in-memory data (Top-300 drug autocomplete, directory/pricing estimates, reservation and claim flows).
- Pharmacy claim and pharmacy dashboard actions exist as MVP/placeholder UI.
- No real backend persistence, verification, or admin workflow exists.
- NPPES extraction outputs were generated into data/ipn/ but the Next.js app currently does not ingest those files.
- Next.js production build is currently failing due to a Turbopack panic in app/globals.css; this is separate from the importer outputs.

1) Consumer Experience
A) Homepage
- Implemented: Yes
- Route/path: /
- File: app/page.tsx
- Functionality: Hero section + nav links (Search, Claim Your Pharmacy, For Pharmacies, Sign in).

B) Drug search
- Implemented: Yes
- Route/path: /search

- Route/path: /reserve

F) Reservation confirmation page
- Implemented: Yes (MVP)
- Route/path: /reservation/confirmation
- File: app/reservation/confirmation/page.tsx

G) Claimed vs unclaimed pharmacy behavior
- Implemented: Yes (mocked)
- Files: app/results/page.tsx and app/lib/ipn-pharmacy-profile.ts; claim status from app/lib/ipn-claims-store.ts

6) Claim Workflow Recommendation (ideal “Claim This Pharmacy”)
Hyper-seamless flow
- After submission:
  - Persist claim request with status “pending_verification”.
  - Show confirmation screen: “We’ll verify and activate within X days.”
- Collect exactly:
  - Pharmacy info (prefilled): name, address, NPI, phone
  - Claimant info: full name, role/title, email, phone
  - Evidence (optional but recommended): doc upload for authorization
  - Notes and preferred contact method
- Verification approach:
  - NPI/address validation
  - authorization verification (email domain match, phone verification, or document review)
- After approval:
  - activate profile: enable pricing upload + reservations
  - notify pharmacy (email) and show admin reference for support

7) Dashboard Recommendation

- View profile (read)

- Minimal edit (address/contact correction)

Nice-to-have later:

Minimum viable admin dashboard
Must-have:

Nice-to-have later:

- Full audit logs

2) Implement admin approval workflow that activates profiles.
3) Implement pharmacy pricing upload + reservation moderation persistence.
4) Ingest NPPES-derived directory seed into the real directory data layer.
5) Stabilize build reliability (separate from importer work).
